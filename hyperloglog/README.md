# HyperLogLog

## Background & Blog Alignment

As part of our blog series on [Probabilistic Data Structures](https://eventuallyconsistentwrites.substack.com/p/probabilistic-data-structures), this repository implements **HyperLogLog (HLL)** and performs various benchmarks for its different layouts as well as against traditional sets to see its advantages.

---

## Project Structure (Where to find what)

The logic is separated into these four files:

### 1. `HyperLogLog.py` (The Data Structure)

This file contains the actual algorithmic implementation.

* **Sparse vs. Dense Mode:** To save even more memory for small datasets, the HLL starts in a "Sparse" mode using an array of 32-bit integers (`array.array('I')`). It bit-packs the index (24 bits) and the value (8 bits) together.
* **The Threshold:** Once the sparse array consumes as much memory as a dense array would, it triggers `_convertToDense()`, transforming into a fixed-size `bytearray`.
* **The Math (`getCardinality`):** Uses the standard harmonic mean calculation, applies a bias correction factor, and smoothly falls back to Linear Counting for very small datasets.
* **The `merge` Function:** Demonstrates how two HLLs can be merged instantly by taking the element-wise maximum of their registers, enabling distributed counting.

### 2. `Benchmark.py` (The Testing Engine)

If you want to change the number of items tested (e.g., from 100k to 10 Million) or change the target error rates, do it here.

* **Deep Memory Profiling:** Standard Python memory checks (`sys.getsizeof`) only measure the pointers of a `set()`, not the actual strings inside it. This engine uses `pympler.asizeof` to recursively calculate the *true* memory footprint of the data structures.
* **Fair Comparisons:** Tests insertions, varying error rates, and sparse-to-dense transitions. It also tests the `merge()` operation by using an in-place `update()` on the Python HashSet to ensure a mathematically fair, apples-to-apples comparison.
* **Intersection Trap:** Benchmarks the accuracy decay when calculating intersections between HLLs using the Inclusion-Exclusion Principle.
* **CSV Exports:** All benchmark results are written to `.csv` files in the `/tmp/` directory (using system defaults) so they can be plotted.

### 3. `Plotter.py` (The Visualizer)

If you want to change the colors, fonts, or chart layouts, edit this file.

* Reads the CSV files generated by the benchmark engine.
* Uses `matplotlib` to generate 10 distinct charts (Memory usage, Accuracy with statistical bounds, Merge times, Error rate comparisons, The Intersection Trap, etc.).
* Applies a custom, clean aesthetic using custom hex colors and handwritten-style fonts.

### 4. `Main.py` (The Entry Point)

This is the orchestrator. It simply configures the `BenchmarkEngine`, runs the data pipeline, and passes the resulting files to the `BenchmarkPlotter`.

## How to Run the Code

### Prerequisites

You will need a few external libraries for hashing, deep memory profiling, and graphing. Install them via pip:

```bash
pip install mmh3 pympler matplotlib
```

### Execution
Simply execute the Main.py file.
```bash
# from the sandbox directory
python3 -m hyperloglog.Main
```
**What to expect:**
- The terminal will output the progress of the benchmarks (inserting items, tracking errors, timing merges).
- The script will generate .csv files with the raw data.
- Multiple graph windows will pop up demonstrating the $O(1)$ memory footprint of the HyperLogLog versus the $O(N)$ memory explosion of the Python HashSet, alongside its mathematical behaviors and limitations.
